## Latency targets

The [load test](../../tests/load/orders.js) enforces the [sizing document](04-tech-dimensioning.md)'s targets (create order < 300 ms, price batch < 50 ms, list orders < 200 ms, p95). The script was written and its logic checked in a Node harness, but **k6 has never run**: no target has been measured yet. Run `docker compose --profile load run --rm k6` with the stack up.

## Mutation testing

**Baseline not measured.** Step C57 (Stryker.NET on the Domain projects, `break` at 70%) was not done. Stryker.NET 5.0.0 does not yet support Microsoft.Testing.Platform, the runner of this repository's xunit v3 projects (see [Stryker issue 3094](https://github.com/stryker-mutator/stryker-net/issues/3094)): in a test run it finds 0 tests. With the packages `Microsoft.NET.Test.Sdk` 18.11.0 and `xunit.runner.visualstudio` 4.0.1 in the Domain test projects it finds the 223 Orders.Domain tests and creates 498 mutants, but those packages are outside the stack table and were not added. Until then, the baseline score and the weekly `mutation.yml` workflow stay pending.
